# 打刻メモ機能 — 要件 Q&A

## 前提

- 現在の打刻（出勤/退勤）にはメモ欄がない
- ゴール: 打刻と一緒にメモを保存でき、勤怠履歴画面で確認できる

---

## 確定仕様まとめ

| 項目 | 仕様 |
|------|------|
| データモデル | `attendance_records` に `memo` カラム1つ追加（VARCHAR(20), nullable） |
| 粒度 | 1レコード（1日）につき1つのメモ。出勤・退勤で共通 |
| 入力の必須性 | 任意（空でも打刻可能） |
| 最大文字数 | 20文字 |
| 文字種制限 | 改行禁止、絵文字禁止、HTMLタグ禁止 |
| 入力 UI | 打刻ボタンの下にテキストフィールドを常時表示 |
| 退勤時の挙動 | 出勤時に入力したメモがテキストフィールドに表示され、上書き編集可能 |
| 履歴画面の表示 | 「備考」列を追加 |
| 編集・削除 | いつでも可能（当日制限なし）。履歴テーブルの備考セルをインライン編集 |
| 退勤時メモ空の場合 | 既存メモを維持する（空で上書きしない） |
| バリデーションエラー | エラーメッセージ表示のみ。打刻自体はブロックしない |
| プレースホルダー | 表示しない |
| 管理者画面 | メモ表示不要 |
| 打刻修正機能 | メモ対応不要（スコープ外） |

---

## データモデル

[Question] メモは出勤・退勤それぞれに付けられるか？それとも1日1つ（レコード単位）か？
[Answer] レコード単位で

[Question] メモの最大文字数は？（例: 50文字、200文字、制限なし）
[Answer] 20文字

[Question] メモは後から編集・削除できる必要があるか？
[Answer] メモの編集削除はできる

---

## UI / UX

[Question] メモの入力は任意（空でも打刻できる）か、必須か？
[Answer] 任意

[Question] メモの入力 UI はどの形式が望ましいか？（例: 打刻ボタンの下にテキストフィールドを常時表示 / 打刻ボタン押下後にダイアログで入力 / 打刻ボタン横に折りたたみで表示）
[Answer] 打刻ボタンの下にテキストフィールドを常時表示

[Question] 勤怠履歴テーブルでのメモ表示方法は？（例: 独立した「備考」列を追加 / 各行をクリックで展開して表示 / ツールチップで表示）
[Answer] 備考列を追加

---

## バリデーション / 制約

[Question] メモに入力できる文字種に制限はあるか？（例: 改行禁止、絵文字禁止、HTML タグ禁止など）
[Answer] 改行禁止、絵文字禁止、HTML タグ禁止

---

## スコープ確認

[Question] 管理者画面（チーム勤怠一覧）でもメモを表示する必要があるか？
[Answer] 必要なし

[Question] 打刻修正（correction）機能にもメモを付けられるようにするか？今回のスコープに含めるか？
[Answer] 不要

## 追加質問（回答を受けて）

[Question] メモの編集・削除は打刻当日のみ可能か？それとも過去の打刻のメモもいつでも編集・削除できるか？
[Answer]いつでも編集・削除可能

[Question] メモの編集 UI はどこに置くか？（例: 勤怠履歴テーブルの備考セルをクリックしてインライン編集 / 編集ボタンで編集ダイアログを表示）
[Answer]インライン編集

[Question] 出勤メモと退勤メモを備考列にどう表示するか？（例: 「出勤: ○○ / 退勤: △△」のようにラベル付きで1セルに並べる / 出勤備考・退勤備考で2列にする）
[Answer]出勤と退勤で合わせて1つのメモ

[Question] 退勤打刻時、出勤時に入力済みのメモはどう扱うか？（例: 退勤時のテキストフィールドに既存メモを表示し上書き可能にする / 退勤時はメモに触れない（編集は履歴画面でのみ行う））
[Answer] 共通のものを使用する。

[Answer]そのまま

[Question] バリデーションエラー時の挙動は？（例: テキストフィールドの下に赤字でエラーメッセージ表示 + 打刻ボタンを押せなくする / エラーメッセージだけ表示して打刻は可能にする）
